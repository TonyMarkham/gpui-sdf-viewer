## THE PRINCIPLE (locked, inherited from VS-11 — now a birth condition)

No threshold or render constant is born into code. Thresholds live in
`config.toml`; geometry numbers live in the export manifests; both are
decoded from game files by the evidence work — never hand-fitted, never
inherited from the POC.

- The config file is the only home of tunable numbers: no Rust consts, no
  literals in source. Generated WGSL takes every number from config, exactly
  as the composite's generated scene does today
  (`sdf-ui/src/state/scene/composite.rs`).
- Numbers the game files do not carry are **reported, not invented** — or
  measured from the reference art with the method stated, which is the
  style authority's own role. Every config/manifest number carries a
  provenance comment naming its source.
- The four shader constants VS-11 slated for deletion (`SDF_NORMALIZER`,
  `BAND_INNER`, `BAND_OUTER`, `INK`) are simply never written. The
  acceptance rule stands: at M4, the overlay render paths contain no
  numeric literals beyond viewport math, and every config/manifest number
  carries a provenance comment.

## THE SHAPE — titles (re-measured by M0; supersedes VS-11's single-ramp shape)

M0 decoded the title channel: it is a **two-shell distance encoding**, not a
single ramp. Each glyph is a soft halo blob with the letterform embedded as a
brighter core; the value distribution of every measured title concentrates
mass in exactly two windows of the per-texture max, and rendering each window
recovers the glow ring and the crisp letterforms respectively (the core band
alone renders legible "CRIMSON DESERT" letterforms from title id 3's DDS).

```toml
[overlays.title_sdf]
# Band fractions of each texture's OWN max — labels.json carries the measured
# per-title normalizer (e.g. 133 for id 2, 134 for id 3), so there is no
# global normalizer constant. Provenance: value distributions measured by
# tools/title-decode.rs (mass concentrates exactly in these windows), and the
# core band visually recovers the letterforms (tools/t3-core.png).
bands = [
    # the halo shell — present in every measured texture, flat in the
    # reference render; ships off, enable via weight (config is the tuning home)
    { low = 0.42, high = 0.55, kind = "band", ink = [0.706, 0.701, 0.685], weight = 0.0 },
    # the letter core: open above, the crisp letterform
    { low = 0.75, high = 0.90, kind = "ramp", ink = [0.706, 0.701, 0.685], weight = 1.0 },
]

[overlays.font_labels]
# The game's own UI font, extracted from pack 0012 (ui/basefont_eng.ttf —
# unencrypted lz4; see §Evidence). Per-language variants exist alongside.
font = "basefont_eng.ttf"
# Sizes from cdcommon_font_eng.css (the css px = map px on the 8192 plane):
size_main = 24.0    # .font-text-main
size_sub  = 18.0    # .font-text-sub-white
# Map-label ink is NOT in any extractable file (the map label materials are
# engine presets); measured from the reference art, darkest-decile method:
ink = [0.588, 0.545, 0.510]
```

- `CompositeBand`/`BandKind` reused verbatim from
  `sdf-offline/src/config/composite.rs` (`band` = hard window, `ramp` =
  open above). No normalizer in band rows: `value = sample.r * 255 /
  normalizer` with the **per-texture** normalizer from the manifest.
- Provenance summary: band windows = measured (distribution + visual
  recovery); title ink = measured from the reference art (darkest-10% of
  warm-classified glyph pixels, land-only sample: (0.706, 0.701, 0.685) —
  the POC's [0.47, 0.46, 0.43] was far too dark and is discarded); label
  ink = measured from the reference art (darkest-8%: (0.588, 0.545, 0.510));
  font sizes = decoded from `cdcommon_font_eng.css`.
- The renderer bakes the bands into the generated title kernel at pipeline
  build, source-keyed like the composite's generation; changing the config
  regenerates the pipelines.

## What VS-20 delivers

The composite/data views render the world-map fields; VS-20 adds the game's
own overlays on top, positioned the way the game positions them:

1. **Settlement images** — the top-view town art
   (`cd_knowledgeimage_worldmapicon_*_topview`) at their faction-node
   positions with the game's own sizes and anchor offsets (VS-10 §2.2).
2. **Labels** — texture-backed region titles (the active-css ∩ keyed set,
   scales 2.2/1.4/0.6/0.5 with the css rotations) plus font-rendered
   town/area/sea labels in the game's own font — every string from
   `region.paloc` (EN = 0020), never a codename.
3. **The world→map projection**, taken from `fieldinfo`, shared by exporter
   and renderer so overlays and fields can never drift.

Non-goals: POI/pin markers (`uimaptextureinfo` — runtime markers, not
placement), the `v_bitmap_*` swap machinery, zoom-dependent icon staging and
label fading, fog-of-war, the abyss view, region polygons.

## The projection

From `fieldinfo.staticinfo`, record `MainField_UIMap_Texture` (key 10): the
window triple `(x_min, z_top, span) = (-16384, 8192, 19456)`
([[concept.game-map-layers]]). The 8192² UI plane and the exported field
share an edge, so field-uv **is** the projection:

```text
u = (x − x_min)/span            px = u · 8192 = (8/19)·(x + 16384)
v = (z_top − z)/span            py = v · 8192 = (8/19)·(8192 − z)   (z north-up; v flips)
```

- The docs' verified sample: `Node_Dem_DemenissCastle` (−8062.0, −3539.0)
  → (u = 0.4278, v = 0.6029) — vertical agrees with the reference render to
  ±0.002 ([[concept.game-map-labels]], [[concept.game-map-icons-poi]]).
- The renderer consumes `u, v` directly: overlay vertices expand
  [map-px rect] → [field-uv] with these formulas, so the existing pan/zoom/
  viewport-clamp machinery ([[interaction.sdf-render-frame]]) applies for
  free. Settlement CSS sizes and anchors are plane px (÷8192 → uv at draw
  time), read verbatim from the manifest.
- Reference-art mapping: the render is the plain field window (identity,
  acc 0.750 — §Evidence #14); comparisons map render px → field-uv by
  ÷(W, H).
- The projection constants live **in the manifests verbatim from
  `fieldinfo`** — the renderer never hardcodes map constants, and the two
  manifest copies are asserted byte-identical at export and load.

## Architecture (VS-10's decisions, unchanged)

1. Overlays are two export manifests, not a scene change. No new reserved
   names in the scene contract ([[concept.sdf-scene-contract]]); the
   renderer draws overlays the way it draws the contour overlay — a separate
   alpha-blended pass over the finished scene frame, run after the scene and
   contour passes.
2. Positions are resolved at export into the two JSONs — no node tables ship
   in the manifests, nothing is pre-baked in pixels; the renderer applies
   the projection at draw time, so the manifests stay resolution-independent.
3. Icons are packed offline into one RGBA8 atlas (`atlas_icons.rgba`); one
   texture, one bind group at runtime. Titles keep their R8 channel in a
   second atlas (`atlas_titles.r8`) and render as distance fields with the
   game's scale/rotation; font labels render from a glyph atlas built with
   the extracted `basefont_eng.ttf`.
4. Scenes never reference overlays — the shell decides, config-driven.

## Data — `settlement.json` and `labels.json`

Built by one export run (`run/overlays.rs`) straight from game data, written
to `<data_dir>/overlays/`. Same shape as VS-10 §4, with the measured
changes:

```jsonc
{
  "version": 1,
  "projection": { "x_min": -16384.0, "z_top": 8192.0, "span": 19456.0, "plane": 8192.0 },
  "atlas": { "file": "atlas_icons.rgba", "size": [4096, 4096], "sha256": "…" },
  "settlements": [
    { "name": "Demeniss", "node": "Node_Dem_DemenissCastle",
      "world": [-8062.002, 586.157, -3539.0],  // verbatim factionnode triple (census rule)
      "rect": [0, 0, 230, 230],
      "size": [230.0, 230.0],                  // CSS px on the 8192 plane
      "anchor": [-50.9, -49.55],               // CSS translate % of element size
      "texture": "cd_knowledgeimage_WorldmapIcon_Town_Demeniss_00_topview",
      "stage": null }
  ]
}
```

```jsonc
{
  "version": 1,
  "projection": { … identical object … },
  "atlas": { "file": "atlas_titles.r8", "size": [2048, 2048], "sha256": "…" },
  "titles": [                           // active-css ∩ regioninfo-keyed
    { "id": 3, "key": 3, "text": "Crimson Desert",
      "rect": [512, 0, 512, 512],
      "normalizer": 134.0,              // measured per-texture max
      "orientation": "axis-aligned",    // "rot90" for the transposed non-square DDSs
      "scale": 2.2, "rotate_z": -21.0,
      "world": [-5533.53, -1019.87] }   // centroid of the region's node set
  ],
  "labels": [                           // font-rendered: towns, areas, seas
    { "key": 1102, "text": "City of Pailune", "kind": "town",
      "world": [-9640.679, 213.728],
      "size": [24.0, 0.0],              // css font px from cdcommon_font_eng.css
      "style": "normal" }               // normal | sea (no tracking — §Evidence #6)
  ]
}
```

Rules:

- A settlement's `world` is the verbatim factionnode triple under the pinned
  census rule; every `settlements[].node` must exist in `factionnode`
  (export rejects, naming the node). Every title/label `key` must resolve in
  `regioninfo` and the loc table (export rejects, naming the key).
- `titles` = the active css rules ∩ regioninfo keys (§Evidence #12); every
  other atlas id — the 51 key-unmatched and the commented-out rules — goes
  to the export log, never into the manifest. Each title carries its
  measured `normalizer` and `orientation`.
- Font-label `size` is the css font size (24px main / 18px sub,
  `cdcommon_font_eng.css`); no letter-spacing exists in the game files —
  reported, not invented (§Evidence #6). A label whose geometry cannot be
  derived is exported with text and anchor only, reported, and renders no
  glyph.
- Label `kind` follows the game's own material taxonomy:
  `upper`/`lower`/`town`/`sea` (from `material-worldmap-region-name-*`,
  `worldmapicon.css:1240-1252`), not the prior export's `area/town`.
- A region whose subtree contains no positioned node is a diagnostic and
  gets no label. `rect` must fit its atlas; sha256 over both atlases is
  verified at load — the field manifest's trust model
  ([[concept.game-data-pipeline]]). The GUI parses no DDS, ever.
- The field manifest gains `world_window` (additive, optional, version
  stays 1); overlays refuse to load against a legacy export with a named
  error.

### Title anchors

The node-set centroid rule is the only game-data anchor available, and the
reference shows it is not the game's rule for titles: the big Crimson Desert
title renders at ≈(fx 0.65–0.75, fy 0.34–0.40) while the centroid projects to
(u 0.558, v 0.473) — a measured delta of ≈0.1 in both axes. Resolution: ship
centroids as the default, and carry per-title measured overrides in config
where the reference allows a measurement:

```toml
[overlays.title_anchors]
3 = [0.70, 0.37]     # measured on REFERENCE-land-map.png (title 3's visible letters)
```

The override keys carry their provenance in the config comment; unmeasured
titles keep centroids. This is a decision, not an open issue: the anchor
mechanism is config-owned, the defaults are game-data-derived, and the
deltas are recorded.

## Work breakdown

### `sdf-offline` — extraction

- `config/extract.rs`: `DEFAULT_PACKS = ["0012", "0008"]`; includes per the
  shipped config (already carries the tile families, the three staticinfo
  tables, the UI files, and `cd_worldmap_regiontitle_*`) **plus**
  `ui/basefont*.ttf` (§Evidence #7). New `[extract] localization_pack =
  "0020"` (docs-resolved; picker overridable). The paloc entry decrypts
  through the proven `paz/crypto.rs` chain ([[concept.game-install-packs]]).
- `run/extract.rs` needs no changes.

### `sdf-offline` — parsing (new module `src/gamedata/`)

- `staticinfo.rs`: shared table reader per [[concept.game-staticinfo]] —
  header stride detection (6 vs 8 bytes), records = key + strlen + name +
  payload; ids read from records, never computed.
- `fieldinfo.rs`: assert `MainField_UIMap_Texture` yields the window triple
  `(-16384, 8192, 19456)`; emit `projection` (and `world_window`).
- `factionnode.rs`: byte-aligned first-triple scan, strict plausibility
  (§Evidence #8); census golden 1093/1119; the unpositioned 26 are
  diagnostics.
- `regioninfo.rs`: the unified grammar (§Evidence #10) — child lists on
  every record (kingdoms' single-child lists included; reject the export if
  any child key fails to resolve, naming the parent), `Region_Node_*` bound
  to factionnode **by name** (a node-region naming a node factionnode lacks
  is a diagnostic).
- `loc.rs`: paloc parser per the settled layout (§Evidence #9) → region key
  → display text; goldens on the four known records. Resolved text is
  written into each entry, never dumped separately.
- `css.rs`: comment-stripping tokenizer for `worldmapicon.css`
  (`WorldmapIcon_Setting_Faction_*` settlement rules; the 38 active
  `worldmap-region-title-<id>` rules with scale/rotate) and
  `cdcommon_font_eng.css` (`font-text-*` sizes/ink/shadow). Comment blocks
  are semantic (§Evidence #12).
- Node ↔ icon binding by name normalization
  (`Node_Cal_CalphadeCastle` → `Castle_Calphade`); misses are diagnostics;
  `[extract.overlays]` carries an override table for stragglers.
- `atlas.rs`: shelf-packed 4096² RGBA icon atlas; titles as R8 rects with
  per-entry `orientation` (§Evidence #13); BC1/3/5/7 decode via
  `texture2ddecoder` behind `dds/decode.rs`; a format we cannot decode
  fails the export naming the file — never a wrong pixel. Each title's
  measured max is written as its `normalizer`.

### `sdf-offline` — export

- New `run/overlays.rs`: one run → `overlays/settlement.json` +
  `atlas_icons.rgba` + `labels.json` + `atlas_titles.r8`; the projection is
  written from one decoded value into both files, byte-identical asserted.
- `export/manifest.rs`: additive `world_window`.

### `sdf-component`

- `src/data/overlay_manifest.rs`: loads both files; verifies the §Data
  rules, the projection-equality, and both atlas sha256s; immutable once
  loaded; failures named like the field manifest's. Reuses the `config:`
  scheme rewriting from the scene loader
  ([[concept.sdf-scene-contract]]).
- `src/renderer/overlays.rs` (sibling of `overlay.rs`): one pipeline,
  instanced draws, alpha blending, run after the contour pass. Uniforms per
  frame: projection constants, view (`view_center`, `params.z`), plane
  size. Icons: RGBA atlas, premultiplied. Titles: R8 channel, coverage from
  the config bands applied over each entry's manifest `normalizer`
  (two bands per THE SHAPE — halo off by weight 0.0, letter core as an
  open-above ramp), rotated and scaled in the shader, ink = the band's ink.
  The title kernel is **generated from the config values at pipeline
  build** — source-keyed, regenerated when the config changes (the
  `CompositeSpec` generation route). Font labels: `ab_glyph` glyph atlas
  built at load from the extracted `basefont_eng.ttf` (the game's own
  font — no stand-in); sizes from the manifest entries; per-label style
  `normal` | `sea` (no tracking — §Evidence #6).

### `sdf-ui` — shell

- `DEFAULT_TEMPLATE` gains:

  ```toml
  [overlays]
  enabled      = true
  titles       = true
  opacity      = 1.0        # 0..=1, both layers
  icon_atlas_size    = 4096
  title_atlas_size   = 2048
  glyph_atlas_size   = 2048

  [overlays.title_sdf]      # THE SHAPE; measured numbers with provenance comments
  …

  [overlays.font_labels]    # §THE SHAPE; css-decoded + reference-measured
  …

  [overlays.title_anchors]  # measured per-title overrides; centroids otherwise
  ```

- `Config::check()` rejects opacity outside 0..=1 and validates band
  edges/weight/ink domains in the composite style. Control bar: one toggle
  + the opacity slider; status bar shows `overlays: N settlements, M
  labels` or the load error verbatim.
