## THE PRINCIPLE (locked)

No thresholding will be a code constant. Thresholds live in `config.toml` —
the repo's standard home for them, the shape the composite bands already
prove. The numbers that ship there are decoded from the game data by the
evidence work — never hand-fitted, never inherited from the POC.

- The config file is the only home of the numbers: no Rust consts, no
  literals in source. The generated WGSL takes every number from config,
  exactly as the composite's generated scene does today.
- The Python POC is not an authority for any number, anywhere.

## THE SHAPE — titles (locked)

```toml
[overlays.title_sdf]
normalizer = 133.0        # measured: atlas byte range, min 0 / max 133
bands = [
    { low = 0.42, high = 0.55, kind = "ramp",
      ink = [0.47, 0.46, 0.43], weight = 1.0 },
]
```

- `CompositeBand`/`BandKind` reused verbatim from
  `sdf-offline/src/config/composite.rs`. No normalizer in the band rows;
  the band domain is normalized SDF units, named by `normalizer`
  (`value = sample.r * 255 / normalizer`).
- Provenance of the shipped numbers: `normalizer = 133.0` is measured this
  session from the atlas byte distribution (min 0 / max 133). The band
  edges and ink are POC-swept values — **not confirmed**; Step 1 re-measures
  them from the atlas and locates the ink in the game files, and whatever
  it finds replaces them. If the game files carry none, that is reported,
  not shipped as a fitted default.
- The renderer reads the bands from the shell's config view and bakes them
  into the generated WGSL (the `CompositeSpec::scene_source` route).
- The four shader constants (`SDF_NORMALIZER`, `BAND_INNER`, `BAND_OUTER`,
  `INK`) are deleted.
- Only the numbers may change; never the shape.

## Steps

### Step 1 — evidence (read-only, no code changes)

Decode title id 3 from `atlas_titles.r8`: measure the glyph-edge window and
the encoded range from the value distribution, render the single-ramp
recovery, compare against the reference map art. Locate the title ink in
game files; record the finding either way — no invented numbers.

### Step 2 — sign-off

Show the decoded images, the measured numbers, and the ink source finding.
Implementation starts only on the user's go.

### Step 3 — config (`sdf-offline`)

`OverlayView` gains `title_sdf` exactly as THE SHAPE. `DEFAULT_TEMPLATE`
gains the block with Step 1's measured numbers. `Config::check` validates
band edges, weight, and ink domains in the same style as the composite
checks. Config tests updated (template/defaults equality). No runtime
rewriting of the user's config — the decoded values ship as the defaults.

### Step 4 — flow (`sdf-ui` → `sdf-component`)

The bands ride `overlay_view()` → `App::load_overlays` → canvas → renderer
(the route the opacity/titles switches already take). The renderer bakes
the band values into the generated title kernel at pipeline build,
source-keyed like `ensure_overlay`; changing the config regenerates the
pipelines.

### Step 5 — shader (`overlays.rs`)

`SDF_NORMALIZER`, `BAND_INNER`, `BAND_OUTER`, and `INK` are deleted. The
title coverage line is generated from the config band values; mixing starts
from transparent, then opacity.

### Step 6 — validation

`cargo fmt`, `cargo check`, `cargo clippy --all-targets -- -D warnings`,
`cargo test --workspace`. Full set; rerun anything a correction touches.

### Step 7 — visual verification

Rebuild, composite tab, screenshot, compare against the reference map art.
Report exactly what is seen.

### Step 8 — font-label evidence pass

Decode from `worldmapicon.thtml` / `worldmapview.css`: the `font-text-*`
label classes' sizes, ink, and the sea style's tracking. `FONT_LABEL_SIZE`,
the font-label `INK`, and `SEA_LETTER_SPACING` leave code to config/export
on this evidence; the label glyph atlas edge joins
`atlas_size`/`title_atlas_size` in config. Whatever the game files do not
carry is reported, not invented.

### Step 9 — composite evidence pass

The `[composite.layer]` band numbers and inks, and `PAPER` in
state/scene/composite.rs, are hand-fitted values — the same violation. This
pass decodes the field edges and map palette from the game data, shows the
finding and the shape it forces, and replaces the fitted values. Config
keeps the layer list and order as tuning.

### Step 10 — contour constant (flagged, separate)

The contour overlay's `INK` (overlay.rs:10) is a pre-existing component
constant. Same rule, its own pass — not silently ignored.
