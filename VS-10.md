# VS-10 — Pan and zoom for the map scenes

## What

Add pan and zoom to the map scenes (the data scenes bound to a VS-20 export
manifest — today `coast`, `river`, `road`, `mountain`, `abyss_hex`, `inspect`).
Scroll zooms about the cursor, left-drag pans, a shell control resets the view.
No scene file changes: the transform lands once in the prelude, so every map
scene and the contour overlay follow automatically.

## Why

The map scenes render the whole field fitted to the canvas. The exported grids
are far larger than one screen's worth of usable detail — the mip chain exists
precisely to be zoomed into — but there is no way to navigate: the LOD slider
changes sampling density over the same full-extent view. Pan and zoom turn the
canvas from a static picture into a map viewer.

## Design

### The transform lives in `field_uv`

The only place canvas coordinates become field coordinates is `field_uv(p)` in
the prelude (`crates/sdf-component/src/scene/mod.rs`, `FIELD_HELPERS`). Every
sampling path goes through it: `field_coord` → `field_lod`/`field_raw` →
`field`, and the contour overlay compiles from the same `field_helpers`
(`crates/sdf-component/src/overlay.rs`). Applying the view there means:

- all map scenes get pan/zoom with zero file changes (the contract keeps
  `field(p)` as the only sampling entry point);
- the overlay tracks the view for free;
- recipe scenes using `fn scene` (SDF shading) are untouched — they never
  reach the field helpers, and the inert 1×1 stub makes the helpers
  meaningless on non-data scenes anyway.

The view is stored in field-uv space, not `p`-space: the fitted mapping
`field_uv` is fraction-based (pixel fraction → uv fraction), so a view
expressed as `(center_uv, zoom)` survives window resizes — the same uv window
re-renders at the new size, and no `aspect` value is ever baked into the
stored state. The shader applies it as an affine map on `field_uv`'s output:

```wgsl
fn field_uv(p: vec2f) -> vec2f {
    let base = /* existing fitted mapping on p */;
    let viewed = (base - vec2f(0.5)) / u.params.z + u.view_center;
    return clamp(viewed, vec2f(0.0), vec2f(1.0 - 1e-6));
}
```

`view_p` becomes a reserved helper expressing the same view back in the
canvas `p` convention (`y` ∈ [-1, 1], `x` ∈ [-aspect, aspect], the space
`u.mouse` uses), so scenes can deliberately map screen to world — e.g. a
cursor-anchored probe under zoom: `view_p(u.mouse)`.

```wgsl
fn view_p(p: vec2f) -> vec2f {
    let uv = field_uv(p);
    return vec2f((uv.x * 2.0 - 1.0) * u.aspect, 1.0 - uv.y * 2.0);
}
```

### Uniform block — same 48 bytes

The block has two zeroed gaps today (the pad at 24..32 and `params.zw`).
Use them; `UNIFORM_SIZE` stays 48:

| bytes  | field        | meaning                                                   |
|--------|--------------|-----------------------------------------------------------|
| 24..32 | `view_center`| field-uv point at the viewport center (default `[0.5, 0.5]`) |
| 40..44 | `params.z`   | zoom factor (default 1.0, clamped [1.0, 64.0])             |
| 44..48 | `params.w`   | reserved (stays 0)                                         |

Changes:

- `UNIFORM_BINDINGS` (`scene/mod.rs`): name the pad `view_center: vec2f`,
  document `params.z` as zoom in the struct comment.
- `UNIFORM_SIZE` doc comment and `uniform_bytes`
  (`crates/sdf-component/src/renderer/mod.rs`): pack the new slots.
- `FrameRequest` (`crates/sdf-component/src/renderer/frame_request.rs`):
  add `view_center: [f32; 2]` and `view_zoom: f32` as explicit fields — the
  request struct mirrors intent, not the buffer layout.

### View state — component-owned

`State` (`crates/sdf-component/src/canvas/state.rs`) gains the view and the
drag bookkeeping, with pure helper functions for the math (unit-testable
without a window):

- `view_center: [f32; 2]` (default `[0.5, 0.5]`), `view_zoom: f32`
  (default 1.0) — both in field-uv space, so window resizes re-render the
  same uv window instead of shifting it (see the transform above).
- `dragging: bool` + last cursor position in viewport fractions.
- Accessors `view_center()`, `view_zoom()`; mutators `zoom_at(anchor, z1)`,
  `pan_by(delta)`, `reset_view()`; `cx.notify()` on change so the canvas
  repaints.
- Anchored zoom keeps the world uv under the cursor fixed
  (`anchor = field_uv_base(cursor)`):
  `center' = center + (anchor - 0.5) * (1 / z0 - 1 / z1)`.
- Drag moves content with the cursor: `center' = center - delta_px / size / z`
  per axis (y sign flipped against screen y, matching the uv flip), then the
  clamp below.
- Viewport clamp: `center ∈ [0.5/z, 1 - 0.5/z]` per axis. The field always
  covers the viewport — no `ClampToEdge` smears at any zoom — and at the
  zoom floor `z = 1` the clamp forces `center = 0.5`, exactly identity, so
  the floor and pan can never disagree (no stuck-off-center views).
- Zoom bounds [1.0, 64.0]: the field fits at 1; past 64 the Inspect scene is
  already showing texel-nearest blocks.
- `set_scene` resets the view to identity when the scene (its data key)
  changes — each scene opens fitted, deterministically.

### Input wiring — `Canvas::paint`

Alongside `track_mouse` (`crates/sdf-component/src/canvas/mod.rs`), register
three handlers via `window.on_mouse_event`; all gated on `state.has_data()`
so non-data scenes leave the wheel alone:

- `ScrollWheelEvent` — zoom factor
  `exp2(-event.delta.pixel_delta(window.line_height()).y * SENSITIVITY)`,
  per-event factor clamped to [0.5, 2.0] to reject huge deltas; the math is
  multiplicative on raw pixel deltas, so trackpads zoom continuously and one
  notched-wheel step (≈ 3 lines) lands near ×1.25 with a single tuned
  `SENSITIVITY` constant. Anchor at the cursor's viewport-fraction position,
  call `zoom_at`.
- `MouseDownEvent` (left) inside the bounds — begin drag, record the cursor
  as a viewport fraction (same inside test as `track_mouse`).
- `MouseMoveEvent` while dragging — `pan_by` the delta and update the
  recorded cursor. Moves outside the bounds keep panning (clamped), so the
  gesture does not stutter at the canvas edge; the matching `MouseUpEvent`
  handler is registered without an inside-bounds check so releasing outside
  the canvas ends the drag.
- The error overlay (a sibling div painted over the canvas) needs no special
  casing: it only shows while the scene/renderer is failing, and view changes
  touch uniforms only.

### Zoom-aware LOD

Zooming in without mip refinement just magnifies blocks. Make the level the
renderer submits (`canvas/mod.rs`, where `level` is derived from
`state.field_level`) zoom-aware:

```text
raw = field_level * (levels - 1) - log2(view_zoom)
level = clamp(round(raw), 0, levels - 1)
```

The LOD slider stays the user's base bias; zoom refines downward toward
mip 0 automatically. `u.params.x` still carries the effective level — no
shader change.

### Shell — control bar

`crates/sdf-ui/src/component/control_bar.rs` + `constants.rs`:

- a "1:1" reset button calling `SdfCanvasState::reset_view`, disabled when
  the active scene has no data (like the other controls);
- a zoom readout (`{zoom ×}`, e.g. `4.0×`) fed from `view_zoom()`.

`App` state needs no new fields — the canvas entity owns everything; the
button and label read/call through it.

## Out of scope

- Pinch gestures and keyboard shortcuts (gpui has `PinchEvent`; later).
- Rotation, zoom-out below 1.0 (letterboxed fit), touchpad two-finger pan.
- Any scene-file change or new scene directive.

## Resolved decisions

No open issues; the five questions raised in review are settled as follows:

1. **Zoom floor vs. pan** — the viewport clamp (`center ∈ [0.5/z, 1 - 0.5/z]`)
   makes the field cover the viewport at every zoom and forces exact identity
   at the floor; a stuck-off-center view is impossible. The reset button stays
   as a convenience, not an escape hatch.
2. **Pan space vs. resize** — the view is stored in field-uv space
   (`view_center`, `view_zoom`), never in `p`-space, so resizing re-renders
   the same uv window instead of shifting it.
3. **Wheel delta** — multiplicative `exp2` on `pixel_delta(window.line_height())`,
   per-event factor clamped to [0.5, 2.0], one `SENSITIVITY` constant
   calibrated to ≈×1.25 per notched step.
4. **Bounds policy** — wheel and mouse-down inside the canvas only; drag
   keeps panning outside (clamped); mouse-up ends the drag anywhere; the
   error overlay gets no special casing.
5. **Test strength** — deterministic pixel assertions through the real
   pipeline: golden frame at identity, constant-fill stub tile under a
   zoomed view.
