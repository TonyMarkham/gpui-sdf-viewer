# VS-200 — Game-Data SDF Scenes (GUI side)

**Goal:** Teach `gpui-sdf-component` (`D:\git\gpui-sdf-component`) to render
the Crimson Desert SDF fields exported by this repo's `map field` step
(`VS-20.md`): a data-texture path through the scene contract, plus one scene
file per layer that re-implements the map pipeline's decode recipes in WGSL.

**Why this doc lives here:** the implementation happens in the GUI repo
(following *its* conventions — its error pattern, its soul annotations, its
scene-contract doc), but it consumes this repo's artifacts and exists to
serve this pipeline. The binding contract between the two sides is the VS-20
export-manifest format; change it in both docs or not at all. Numbered 200
to sit clearly above the map-repo slice numbers (VS-10, VS-20).

## Current state (2026-09-10)

- Scenes are **procedural WGSL only**: `SdfScene` splices a scene body
  between a fixed prelude and rasterizer; `renderer.rs` binds exactly one
  resource — the uniform buffer (`binding 0`). There is no texture binding,
  no image loading, no data path of any kind.
- Scenes come from embedded examples or from files scanned in `scenes/`
  (`SDF_SCENES_DIR` override); header directives (`// sdf-scene: name`,
  `animated`), entry-point rules, and failure modes are documented in the
  GUI repo's `docs/concept.sdf-scene-contract.md` and the `SdfScene` doc
  comment.
- The default shading (`scene_shaded`) derives gradient normals from the
  scene function — correct for a true signed distance, meaningless for the
  game fields, which are **raw coverage bytes, not normalized SDFs**.
- Renderer facts that constrain this slice: uniform block 48 bytes with a
  spare `params: vec4f`; ring of 3 staging buffers for CPU readback; frames
  rendered to an offscreen texture and handed to gpui as `RenderImage`.

## Contract extension

Two directives. The scene contract gains:

```text
// sdf-scene: data  = "manifest.json"
// sdf-scene: layer = "coast"
```

- `data` names a VS-20 export manifest, resolved **relative to the scene
  file**; `layer` selects the entry in the manifest's `layers` array by
  `name` (hard error if absent). The entry is self-contained — edge, payload
  paths, hashes, and the tile table all live on it; there is no index to
  resolve and no reference to chase. A scene directory stays
  self-contained: drop in `.wgsl` + manifest + payloads, done. The
  `SDF_SCENES_DIR` mechanism already decides where scenes live; the
  manifest's own directory decides where data lives.
- On this checkout the export lives at
  `D:\git\cd-data-extract\.work\fields` — the map repo's `config.toml`
  `[paths] work_dir` joined with `[sdf.export] dir`; `manifest.json` and
  the payload `.r8` files sit side by side in it. A scene consuming the
  data in place resolves `data` relative to its own file onto this
  directory.
- Parsing: extend the directive loop in `SdfScene::from_str` (it already
  splits `key = value`); `SdfScene` gains `data: Option<SceneData>` where
  `SceneData` holds the level table — level 0 (`edge`, resolved payload
  path, expected sha256) plus the manifest's `mips` entries — all taken from
  the manifest entry, never guessed. The GUI parses no DDS, ever: the map
  repo already serialized which levels exist.
- Loading a data scene: parse manifest → resolve the `layer` entry → for
  level 0 and every `mips` entry: resolve the payload in the manifest's
  directory → read → **verify sha256** → check `len == edge_k²` → upload at
  its level. The manifest is the trust anchor; the component never infers
  dimensions from file size.
- The prelude's reserved-name list (`u`, `sd_*`, `op_*`, `rot`) grows by the
  new helper (below). The contract doc and the `SdfScene` doc comment are
  updated in the same change — the contract is documented where it lives.

## Renderer changes

- **Bind group layout** gains two entries: binding 1 `texture_2d<f32>`,
  binding 2 `sampler` (filtering, linear, clamp-to-edge). Scenes *without*
  data bind a 1×1 zero-fill `r8unorm` texture, so one pipeline and one bind
  group shape serve both scene classes — no pipeline permutation, no
  conditional shader path.
- **Texture creation:** `r8unorm`, `edge × edge`, `mip_level_count =
  1 + mips.len()` from the manifest entry, usages
  `TEXTURE_BINDING | COPY_DST`, one `queue.write_texture` upload per level
  at scene load. 8192 is *exactly* wgpu's default `max_texture_dimension_2d`
  — the VS-20 edge fits the default limits precisely (mips only shrink);
  anything larger is rejected with the device limit named in the error, not
  truncated.
- **Sampling:** explicit level via `textureSampleLevel`, linear filtering —
  this mirrors the map repo's bilinear-upsample law (upsample the field,
  never resize decoded masks). Address mode clamp so edge texels don't wrap
  into seams.
- **Prelude helpers:**

```wgsl
fn field_lod(p: vec2f, level: f32) -> f32 {
    let uv = vec2f((p.x / u.aspect + 1.0) * 0.5, 1.0 - (p.y + 1.0) * 0.5);
    return textureSampleLevel(t_field, s_field, uv, level).r;
}

fn field(p: vec2f) -> f32 {
    return field_lod(p, u.params.x);
}
```

  `u.params.x` is the mip-level selector, defaulting to 0.0, and
  `u.params.y` is the contour-overlay band width (0.0 = off — see the
  overlay section below; the uniform block's spare `params: vec4f` carries
  both). Layer scenes call `field(p)` and are unaffected; the
  v-flip is a named constant in the prelude until calibrated (below); the
  mapping statement lives in exactly one place, not in every scene.
- **Memory/perf:** ~85 MiB upload per scene load at the full 8192→1 chain
  (64 MiB level 0); the staging ring, readback, and presentation paths are
  untouched. Non-animated data scenes re-render on resize only, same as
  today.

## Scene files (one per layer)

Every game-data scene uses the **`render()` override, not `scene()`**: the
built-in shading assumes a distance field with a meaningful gradient; the
game fields are coverage bytes, so each scene samples
`field(p) * 255.0` and re-implements its recipe from the map repo's
`config.toml`:

| Scene | Recipe (config `[sdf]`) |
|---|---|
| coast | smoothstep band 122..132, zero level 128 |
| river | trench: value ≥ 32 and < 108 (shape, not range, separates channel from shore) |
| road | band 116..136 |
| mountain | hatch: core 120..130 × 0.32 + halo 96..118 × 0.14, clamped |
| abyss_hex | band 120..134 |

- Thresholds are hardcoded in the scene files; `config.toml` stays
  authoritative, and the VS-20 manifest deliberately carries no recipe copy
  (values the export step never consumed don't belong in its provenance).
- Styling is ours to own: facts (bytes, thresholds) crossed the repo
  boundary; the visual treatment (colors, hatch rendering) is new expression,
  not extracted art.
- First pass renders straight coverage (ink on paper); fancy shading is a
  later iteration, not a gate.

Plus one debug scene:

- **inspect** — nearest-neighbor raw-byte view with the mip level bound to
  `u.params.x` (slider). Renders stub placement, tile seams, and the full
  chain the manifest declares. This is also the LOD ground-truth tool: if
  the game's own mips stay recipe-compatible (byte distributions unchanged
  per level), our thresholds hold at every zoom; if the game re-encoded the
  chain (distance-corrected mips are a common trick), the drift is visible
  here first — a fact about the format no other view exposes.

## Contour overlay (UI toggle)

A component-level overlay, **not a scene**: a second fragment pass, run
after the scene pass and before staging readback, sampling the data texture
already in the bind group and alpha-blending contour lines over whatever
scene is active. The toggle and a density slider live in `sdf-ui` beside
the canvas; both map to one uniform, `u.params.y` (0.0 = pass skipped, else
band width in field bytes).

```wgsl
let v = field_lod(p, u.params.x) * 255.0;
let band = fract(v / u.params.y);
let aa = fwidth(v / u.params.y);
let line = 1.0 - smoothstep(0.0, aa * 1.5, min(band, 1.0 - band));
```

- **Why a pass and not a scene:** scenes stay oblivious — the overlay works
  over all five layer scenes and inspect alike, embedded examples without
  data simply don't get the pass (the component knows whether a data
  texture is bound), and no scene file grows a non-recipe concern. The
  same one-bind-group-shape rule as the renderer changes: no pipeline
  permutation, one optional pass.
- **Why before readback:** captured/staged frames carry the overlay, so
  100%-zoom crops for the crops gate show band boundaries — the overlay
  becomes verification evidence, not just eye candy.
- **Why contours at all:** the game fields are monotone distance-like
  scalars, and a quantized distance field *is* a topo map — the POC's band
  visualizations (`viz_land_bands.png`) showed exactly this. Band
  boundaries double as threshold candidates when tuning a recipe in WGSL:
  slide the density until a band edge sits on the feature, read off the
  value, paste it into the scene constant. The overlay is also the primary
  consumer of the `blur_height` field (VS-20): a pure heightmap with no
  recipe scene of its own, viewed via the inspect scene + contour bands.
- Overlay styling (ink color, line weight) is presentation, owned by the
  component theme — the same styling-not-facts line as the scenes.

## Orientation calibration

The v-flip constant starts **documented, not trusted** — tile-grid row 0's
geographic meaning is unknown until checked (same trap class as the map
repo's "32768 is virtual" incident). Gate: the Hernand-bay coastline at
field coords (6016, 3072) must land where the map repo's
`work/layer-coast-hernand-bay.png` crop puts it. Mirrored output → flip the
prelude constant once; never per scene, never per layer.

## Failure modes

Missing or malformed manifest, unknown `layer` key, any level's payload
missing, length ≠ edge_k², sha mismatch, edge above the device limit: all
surface through the existing scene-load error path — canvas overlay + status
bar, last good frame keeps presenting (the contract's documented failure
mode). The GUI repo's error pattern (`UiError::scene`, constructors with
location) carries these; nothing panics, nothing is silently dropped.

## Done criteria

- [ ] Five data scenes render the VS-20 exports; Hernand bay / river
      junction / mountain hatch agree with the map repo's `[layer]` crops at
      100% zoom — crops, not previews (VS-10 rule 1).
- [ ] Corrupted payload (sha mismatch) and truncated payload produce clean
      load errors with the offending path and hash named — for every level,
      not just mip0.
- [ ] The inspect scene steps through every level the manifest declares;
      the level count matches without the GUI repo parsing a single DDS
      byte.
- [ ] The contour overlay toggles over every data scene, scales with its
      density slider, and is absent from the frame when off (and when no
      data is bound).
- [ ] Embedded examples and no-data scenes render unchanged (the 1×1
      default bind keeps the no-data path inert).
- [ ] GUI repo updated coherently: scene-contract doc, `SdfScene` doc
      comment, soul annotations on the touched steps.

## Open decisions

- **Multi-field compositing:** the four distinct fields fit one rgba8unorm
  texture (256 MiB) — a later scene could blend coast + road + mountain in
  one pass; the manifest already serializes every layer self-contained, so
  this needs only
  extra `data`/`layer` directive pairs (and a packed-upload path) first.
- **Thresholds via uniforms:** the spare `params.zw` could carry layer
  thresholds from UI sliders instead of hardcoded scene constants — nice for
  the tune loop, unnecessary for rendering the approved recipes (`params.x`
  is the mip-level selector, `params.y` the contour band width).
